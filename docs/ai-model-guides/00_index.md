# AI Model Guides — Claude Code モデル別プロンプト最適化リファレンス

このディレクトリは、Claude Code でコーディングする際に **どの開発タスクを、どのモデル（Fable 5 / Opus 4.8 / Sonnet 5）に、どんな形式で依頼するか** を判断するための運用リファレンスです。

## 設計の前提（重要）

このリファレンスは 2 層で構成されています。混同を避けるため、各記述には必ずタグが付いています。

- **`[Official]`** … Anthropic 公式ドキュメントで確認できる事実。`source_id` で `01_sources_evidence.md` に紐づく。
- **`[Heuristic]`** … このプロジェクト固有の運用仮説・経験則。公式の裏付けはない。`Confidence` 付き。

**`[Official]` と `[Heuristic]` を絶対に混同しないこと。** 「公式がそう言っている」のか「自分たちがそう運用すると決めた」のかが曖昧になると、半年後にこのドキュメント全体の信頼性が崩れる。

## ファイル構成と読み込みルール

Claude Code に **毎回すべてを読ませない**。model-router skill（SKILL.md）は、フェーズ1
（判定）で `02` のみ、フェーズ2（実行）で実行モデルのガイド（`03`〜`05` のいずれか1つ）のみを
読む。`00`（本ファイル）と `01` は人間の参照・メンテナンス用で、skill は読まない。

| ファイル                       | 中身                                  | いつ読むか                                     |
| ------------------------------ | ------------------------------------- | ---------------------------------------------- |
| `00_index.md`（本ファイル）    | 全体の使い方・読み込みルール          | 人間が最初の一度だけ                           |
| `01_sources_evidence.md`       | 根拠台帳（source_id ↔ 公式主張）      | 記述の裏付けを追いたいとき／更新時（人間向け） |
| `02_model_selection_matrix.md` | タスク × モデル × 指示テンプレ 判断表 | **skill のフェーズ1でモデルを選ぶたび（最頻出）** |

## 30 秒で分かる要約

- **迷ったら Opus 4.8。** 複雑なエージェント型コーディング・エンタープライズ作業の既定の出発点。`[Official]` (S1)
- **最高能力が要るなら Fable 5。** 人間が数時間〜数週間かける、長時間・曖昧・端から端までの作業向け。`[Official]` (S2, S3, S9)。速い対話に使わないのは公式レイテンシ事実から導く運用判断。`[Heuristic]` (S10 の結論部)
- **速度と知性のバランスなら Sonnet 5。** 日々の反復実装の主力。コーディング・エージェント作業に特に強く、Opus 級に移らず高い能力が要る場面の選択肢。`[Official]` (S11)
- **model と effort は別の軸。** model は「どれだけ有能か」、effort は「どれだけ徹底的か」。うまくいかない時は、ノブを回す前にまずコンテキスト（プロンプト・CLAUDE.md・スコープ）を点検する。ノブを回すなら症状で切り分ける：検証不足（ファイル飛ばし・テスト未実行・見直し不足）→ effort ↑、コンテキストが揃って明らかに試みたのに誤り → モデル ↑。effort はモデル切替より良いレバーであることが多いが、それは切り分けの結果として選ぶもので「最初に回す既定」ではない。`[Official]` (S69, S67, S68, S6)
