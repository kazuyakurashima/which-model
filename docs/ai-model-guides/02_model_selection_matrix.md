# 02. モデル選定判断表（Task × Model × 指示の型）

**このファイルがこのリファレンスの中心。** Claude Code で開発タスクに着手するたびに、まずここを見る。

Last verified: 2026-07-05

## 使い方

1. これから行うタスクの行を探す。
2. 第一候補モデルを選ぶ（コスト・速度の制約があれば第二候補へ）。
3. 「指示の型」に従ってプロンプトを組む。詳細な最適化は各モデルの `03/04/05` を参照。

**タグの意味**：`[Official]` = 公式裏付けあり（source_id）。`[Heuristic]` = プロジェクト運用仮説（Confidence 付き、公式裏付けなし）。

## 判断の土台（公式ポジショニング）

- 迷ったら **Opus 4.8**（複雑なエージェント型コーディング・エンタープライズ作業の既定の出発点）。`[Official]` S1
- 最高能力が要る、人間が数時間〜数週間かける長時間・曖昧・端から端まで → **Fable 5**。`[Official]` S2, S9
- 速い対話・高頻度・低コストの主力 → **Sonnet 5**。Fable 5 は速い対話には不向き。`[Official]` S10, S11
- **モデルを変える前に effort を調整する**（単一モデル内で知性↔速度/コストを動かせる）。`[Official]` S6

## タスク別の根拠内訳

上表の第一/第二候補の根拠を、公式と仮説に分けて明示する。

### アプリ初期設計・要件定義 → Fable 5
- **`[Official]`** Fable 5 は長時間・曖昧・端から端までの作業に効果的（S9）。ゴール＋理由の与え方、過剰計画の抑制（S23）、難易度上端から始める（S21）。
- **`[Heuristic]`** 設計・要件はプロジェクトで最も影響が大きく、$50/MTok の出力コストを払う価値がある局面。 / Confidence: Medium / Basis: 公式ポジショニング（S2, S9）＋プロジェクトの重要度判断。

### 実装（通常・反復） → Sonnet 5
- **`[Official]`** Sonnet 5 は速度と知性のバランスで、コーディング・エージェント作業が最大の向上点（S11, S12）。字義的解釈のためスコープ明示が要る（S39）。
- **`[Heuristic]`** 日々の反復実装は量が出るため、$3/$15 の Sonnet 5 を主力にしコストを抑える。 / Confidence: High / Basis: 公式の価格・ポジショニング（S11, S15）＋高頻度タスクという性質。

### 実装の難所・デバッグ → Opus 4.8
- **`[Official]`** Opus 4.8 は複雑なエージェント型コーディングの既定（S1）。推論をツールより優先する傾向で、effort を上げるとツール使用が増える（S32）。xhigh がコーディングに最適（S7）。
- **`[Heuristic]`** 難所は Fable 5 でも良いが、コスト（$5/$25 対 $10/$50）と、対話的に詰める場面が多い点で Opus 4.8 を優先。 / Confidence: Medium / Basis: 公式ポジショニング＋コスト・対話性の判断。

### 大規模リファクタ・レビュー → Fable 5
- **`[Official]`** Claude Code で Fable 5 は一度に収まらない大きなタスクに適する（S50）。検証サブエージェントが自己批判より優れる（S22）。
- **`[Heuristic]`** レビューは「別の目」が価値。生成に使ったのと別モデル/別コンテキストで検証すると差分が見えやすい。 / Confidence: Medium / Basis: 公式の検証サブエージェント推奨（S22）＋レビューの独立性という一般原則。

### UI/UX → Opus 4.8
- **`[Official]`** Opus 4.8 は強いデザイン既定（クリーム/セリフ/テラコッタ）を持ち、編集・ホスピタリティ・ポートフォリオ向き。ダッシュボード・開発ツール・フィンテック等には不向きなので、その場合は具体的方向を明示（S37）。
- **`[Heuristic]`** 開発ツール系の UI が多いなら、既定デザインが合わないため方向指定が必須。用途次第で Sonnet 5 でも可。 / Confidence: Medium / Basis: 公式のデザイン既定記述（S37）＋作るアプリの種類。

## 迷ったときの分岐（フローの言語化）

1. **速い対話 or 高頻度 or 単純？** → Sonnet 5。Fable 5 は使わない（S10）。
2. **複雑なエージェント型コーディング or 迷っている？** → Opus 4.8（S1）。まず effort=high、難所は xhigh（S7）。
3. **人間が数時間〜数週間かける、長時間・曖昧・端から端まで？** → Fable 5（S9）。ただしタイムアウト・進捗・フォールバックを事前設計（S25, S29）。
4. **それでも品質が足りない？** → モデルを上げる前に effort を上げる（S6, S40）。

## 注意（データ保持）

- **Fable 5 は 30 日データ保持が必須で ZDR 不可・Covered Model 指定。** 学生情報など機微データを扱うパイプラインで ZDR 前提のときは Fable 5 を避け、Opus 4.8 を使う。`[Official]` S16
