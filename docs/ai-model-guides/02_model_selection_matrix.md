# 02. モデル選定判断表（Task × Model × 指示の型）

**このファイルがこのリファレンスの中心。** Claude Code で開発タスクに着手するたびに、まずここを見る。

Last verified: 2026-07-06

## 使い方

1. これから行うタスクの行を探す。
2. 第一候補モデルを選ぶ（コスト・速度の制約があれば第二候補へ）。
3. 「指示の型」に従ってプロンプトを組む。詳細な最適化は各モデルの `03/04/05` を参照。

**タグの意味**：`[Official]` = 公式裏付けあり（source_id）。`[Heuristic]` = プロジェクト運用仮説（Confidence 付き、公式裏付けなし）。

**タグ規律の例外**：下の「タスク別判断表」のセルは読みやすさ優先の無タグ要約（Official と Heuristic の混合）。各行の根拠とタグは「タスク別の根拠内訳」セクションが正式に担保する。

## 判断の土台（公式ポジショニング）

- 迷ったら **Opus 4.8**（複雑なエージェント型コーディング・エンタープライズ作業の既定の出発点）。`[Official]` S1
- 最高能力が要る、人間が数時間〜数週間かける長時間・曖昧・端から端まで → **Fable 5**。`[Official]` S2, S9
- 速い対話・高頻度・低コストの主力 → **Sonnet 5**。`[Official]` S11 ／ 「Fable 5 は速い対話・高頻度には使わない」は公式事実（比較レイテンシ「Slower」・単一リクエスト数分・価格 2 倍 — S10）から導く運用判断。`[Heuristic]` / Confidence: High / Basis: S10 の公式事実。
- **モデルを変える前に effort を調整する**（単一モデル内で知性↔速度/コストを動かせる。low は短い・レイテンシ重視の作業、medium はコスト重視のバランス）。`[Official]` S6, S65
- **指示は明確・明示的に。** 「上をいく」挙動が欲しいなら明示的に要求する。文脈の乏しい同僚に見せて従えるか、が黄金律。`[Official]` S46
- **effort の既定は high（Claude API・Claude Code とも）。** 公式推奨：Opus 4.8 のコーディング・高自律作業は **xhigh を明示指定**、Sonnet 5 は最難タスクのみ xhigh、Fable 5 は high 開始で足りる（低 effort でも旧モデルの xhigh を超えうる）。`[Official]` S7

## 注意（refusal リスク）

- **Fable 5 の安全分類器は、攻撃的サイバー技術・生物/生命科学・思考抽出を対象とし、良性のセキュリティ作業や有益なライフサイエンスタスクでも誤検知しうる。** Sonnet 5 も禁止・高リスクなサイバー話題で refusal を返しうる。`[Official]` S28, S44
- 該当が予想される場合は **Opus 4.8 を優先**するか、API 利用時は refusal フォールバック（`fallbacks` パラメータ〈beta〉等）を明示設定する。Claude Code は分類器がフラグしたリクエストに対して自動モデルフォールバックが働く。`[Official]` S29

## タスク別の根拠内訳

上表の第一/第二候補の根拠を、公式と仮説に分けて明示する。

### アプリ初期設計・要件定義 → Fable 5

- **`[Official]`** Fable 5 は長時間・曖昧・端から端までの作業に効果的（S9）。ゴール＋理由の与え方、過剰計画の抑制（S23）、難易度上端から始める（S21）。
- **`[Heuristic]`** 設計・要件はプロジェクトで最も影響が大きく、$50/MTok の出力コストを払う価値がある局面。 / Confidence: Medium / Basis: 公式ポジショニング（S2, S9）＋プロジェクトの重要度判断。

### 大規模リファクタ・移行 → Fable 5

- **`[Official]`** Claude Code で一度に収まらない大きなタスクに適する（S50）。長時間・端から端までの作業に効果的（S9）。検証サブエージェント（別コンテキスト）が自己批判より優れる（S22）。
- **`[Heuristic]`** 影響範囲が広く手戻りコストが大きい局面であり、$10/$50 を払う価値がある。対話的に段階を刻んで進めたい場合は Opus 4.8（第二候補）。 / Confidence: Medium / Basis: 公式ポジショニング（S9, S50）＋プロジェクトの重要度判断。

### 実装（通常・反復） → Sonnet 5

- **`[Official]`** Sonnet 5 は速度と知性のバランスで、コーディング・エージェント作業が最大の向上点（S11, S12）。字義的解釈のためスコープ明示が要る（S39）。
- **`[Heuristic]`** 日々の反復実装は量が出るため、$3/$15 の Sonnet 5 を主力にしコストを抑える。 / Confidence: High / Basis: 公式の価格・ポジショニング（S11, S15）＋高頻度タスクという性質。

### 実装の難所・デバッグ → Opus 4.8

- **`[Official]`** Opus 4.8 は複雑なエージェント型コーディングの既定（S1）。推論をツールより優先する傾向で、effort を上げるとツール使用が増える（S32）。コーディング・高自律作業は xhigh の明示指定が公式推奨（S7）。
- **`[Heuristic]`** 難所は Fable 5 でも良いが、コスト（$5/$25 対 $10/$50）と、対話的に詰める場面が多い点で Opus 4.8 を優先。 / Confidence: Medium / Basis: 公式ポジショニング＋コスト・対話性の判断。

### コードレビュー → 通常は Opus 4.8、大規模・独立監査は Fable 5

- **`[Official]`** Opus 4.8 は複雑なエージェント型コーディングの既定（S1）で、レビューでも「高severityのみ」等の指示を字義通り守るため、全件報告＋下流フィルタの設計が要る（S54）。Fable 5 の比較レイテンシは「Slower」で単一リクエストが数分に及ぶ（S10）。
- **`[Official]`** 大規模・独立監査（一度に収まらない規模の変更、生成に使ったのと別の目での検証）には Fable 5 が適する（S50）。検証サブエージェントが自己批判より優れる（S22）。
- **`[Heuristic]`** 「別の目」の価値は生成モデルと異なるモデル/コンテキストで検証する点にある。通常の PR レビューは高頻度・対話的なタスクであり、日常的な PR レビューにまで Fable 5 を使うのはコスト（$10/$50）に見合わないことが多い。 / Confidence: Medium / Basis: S10 の公式事実（レイテンシ・価格）＋レビューの独立性という一般原則。

### UI/UX → Opus 4.8（Sonnet 5 も可）

- **`[Official]`** Opus 4.8 は強いデザイン既定（クリーム/セリフ/テラコッタ）を持ち、editorial・ホスピタリティ・ポートフォリオ向き。ダッシュボード・開発ツール・フィンテック等には不向きなので、その場合は具体的方向を明示（S37）。Sonnet 5 にも類似の既定スタイル収束があり、具体的指定または複数案提示が有効（S59）。
- **`[Heuristic]`** 開発ツール系の UI が多いなら、既定デザインが合わないため方向指定が必須。一発の完成度を重視するなら Opus 4.8、反復速度重視なら Sonnet 5。 / Confidence: Medium / Basis: 公式のデザイン既定記述（S37, S59）＋作るアプリの種類。

### テスト設計 → Sonnet 5

- **`[Official]`** コーディング・エージェント作業で Sonnet 5 が最大の向上点（S12）。字義的解釈のため境界・異常系は明示列挙が要る（S39）。
- **`[Heuristic]`** テストは反復性が高く量が出るため、$3/$15 の Sonnet 5 でコストを抑える。 / Confidence: Medium / Basis: 公式の価格・ポジショニング（S15）＋高頻度タスクという性質。

### ドキュメント作成 → Sonnet 5

- **`[Official]`** 応答長をタスクの複雑さに合わせ、正の例が否定指示より効く（S38, S39）。
- **`[Heuristic]`** ドキュメントは量が出る反復作業であり、Sonnet 5 が主力に適する。 / Confidence: Medium / Basis: 公式の価格・ポジショニング（S15）。

### 短い調査・要約 → Sonnet 5（effort=low）

- **`[Official]`** Fable 5 の比較レイテンシは「Slower」で、価格は Opus 4.8 の 2 倍（S10）。短くスコープされたタスク・レイテンシ重視は low effort が適する（S65）。
- **`[Heuristic]`** 単純な質問応答に高い effort や高価なモデルを充てるのはコスト過剰。Fable 5 は使わない。 / Confidence: High / Basis: S10 の公式事実＋コスト最小化の一般原則。

### 長時間・自律実行 → Fable 5

- **`[Official]`** 人間が数時間〜数週間かける長時間・曖昧・端から端までの作業に効果的（S9）。並列サブエージェントへの委譲が信頼でき、非同期に進めるのが優る（S55）。進捗報告はツール結果との突き合わせで検証させる（S56）。
- **`[Heuristic]`** ルーチン部分は effort を落として（low/medium）コストを抑えられる。 / Confidence: Medium / Basis: 公式の effort スイープ推奨。

## 迷ったときの分岐（フローの言語化）

1. **速い対話 or 高頻度 or 単純？** → Sonnet 5。Fable 5 は使わない（S10 の公式事実に基づく運用判断）。
2. **複雑なエージェント型コーディング or 迷っている？** → Opus 4.8（S1）。コーディング・高自律作業は xhigh を明示指定（S7）。
3. **人間が数時間〜数週間かける、長時間・曖昧・端から端まで？** → Fable 5（S9）。ただしタイムアウト・進捗・フォールバックを事前設計（S25, S29）。
4. **それでも品質が足りない？** → モデルを上げる前に effort を上げる（S6）。

## 注意（データ保持）

- **Fable 5 は 30 日データ保持が必須で ZDR 不可。** `[Official]` S16。学生情報など機微データを扱うパイプラインで ZDR 前提のときは Fable 5 を避け、Opus 4.8 / Sonnet 5 を使う（Sonnet 5 の ZDR 可は公式確認済み。Opus 4.8 の ZDR 可は要原文再確認 — 01 の検証状態注記を参照）。

## 注意（Haiku 4.5 について）

このリファレンスは Fable 5 / Opus 4.8 / Sonnet 5 の 3 モデルに意図的に絞っている。`claude-haiku-4-5`（$1/$5、最速ティア・near-frontier の知能）は対象外 — 単純作業でコスト最小化が最優先の場合は別途検討すること。`[Official]` S66
