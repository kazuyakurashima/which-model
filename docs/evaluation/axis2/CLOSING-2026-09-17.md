# 軸2 価値検証 v3：終了記録

作成：2026-09-17 ／ この文書は凍結対象外（実験の終了時に書いた記録）

---

## 1. 結論

判定者の意見が割れた組は **20組中11組** で、停止規則4の閾値（1/3）を超えた。
人間確認を行ってもこの割合は変わらないため、確認を省略して実験を終了する。
事前に定めた完了条件（割れた組の人間確認）は満たしておらず、機械集計（`REPORT.md`）は
**INCOMPLETE のまま保存する。**

**本実験から、整形の効果は判断できない。** この方法・規模では、整形の効果を確認できなかった。
価値があるとも無いとも言わない（`STOP-RULES.md` §2）。

which-model の開発は、これを受けて終了する。理由は **価値を示せなかった** ことであって、
価値がないと分かったことではない。

## 2. 何を確かめようとしたか

- **問い**：同じモデル・同じ effort で、素の依頼（A）と which-model が整形した依頼（B）のどちらの回答が、
  依頼者にとって有用か
- **タスク**：作者の実際の依頼10件。読み取り専用。
  7件は同じ私有リポジトリ、2件は別の私有リポジトリ（どちらも固定したコピーを参照）、
  1件（t06）はリポジトリを参照しない
- **モデルは人手で割り当てた**：Sonnet 5 / medium（t01・t02・t03・t10）、Opus 5 / high（t04・t05・t06）、
  Fable 5.1 / high（t07・t08・t09）
- **B の作り方**：空のフォルダで Opus 5 に `/which-model:pick <素の依頼>` を実行し、候補からは選ばずに
  割り当てたモデルと effort を指定して、そのモデル向けに整形させた。20本とも、出力の「確定モデル」行が割当と一致した
- 各タスク2回（B は回ごとに作り直した）→ **回答40件・比較20組**。回答を生成したモデルは、40件とも起動記録で指定どおりだった
- **判定**：Claude（`claude-opus-5` / high）と Codex（`gpt-6-astra` / high）が、各組を左右入れ替えて2回ずつ判定した（計80回）。
  判定の優先順位は、正しさ → 目的の達成 → 重大なリスクや条件の抜け → 余計な説明・作業の少なさ → すぐ使えるか
- 停止規則と判定の仕組みは、回答を生成する前に凍結した（`manifest.json`。2026-09-17 時点で87ファイルとも一致）

## 3. 判定の割れ方

`REPORT.md` §2 の内訳を分類した。

| 割れ方 | 組数 | 比較単位 |
| --- | ---: | --- |
| 2つの判定者がそれぞれ答えを出したが、A と B で正反対 | 4 | t03_r2・t04_r1・t06_r2・t10_r1 |
| 2つの判定者がそれぞれ答えを出したが、一方は勝ち・他方は引き分け | 4 | t01_r2・t05_r1・t07_r2・t08_r1 |
| 少なくとも一方の判定者が、左右を入れ替えた2回で違う答えを出した | 3 | t01_r1・t02_r1・t06_r1 |
| **計** | **11** | |

2つの判定者の答えが揃ったのは20組中9組だった。
設計時は、人間確認の量を見積もるために一致率を75%と仮置きしていた。
その前提を確かめるはずだった、v2 への後付け判定（`DESIGN.md` §6）は行っていない。

**割れた11組の判定理由は読んでいない。** 終了の判断に必要ないためである。

### 盲検が崩れうる2組を除いた場合

作り直した B のうち2本（`t05_docs_grouping_r2`・`t08_jwt_role_design_r1`）に「which-model」という語が入っていた。
事前の取り決めにより、再生成せず「盲検が崩れうる」組として扱う。

- この2組を除くと、割れた組は **18組中10組（約56%）** で、規則4の閾値を引き続き超える
- 回答40件には「which-model」という語は出ていない（判定の完了後に件数だけを数えた）

---

## 4. 人間確認を行わない理由

規則4は、**2つの判定者の答えが食い違った組の割合**で決まる。人間確認は、食い違った組の勝者を決めるための手順であり、
食い違いの件数そのものは変えない。11組すべてを人間が確認しても割合は55%のままで、規則4の結論（判定不能）は変わらない。

**`human/*.json` は作っていない。** 人間が判定していないのに作ると、記録の捏造になる。
このため集計コードの完了条件は満たされず、`REPORT.md` の状態は INCOMPLETE のままである。

## 5. REPORT.md の数字の扱い

`REPORT.md` には、タスク単位の勝敗（B勝ち 0 ／ A勝ち 1 ／ 保留 9）、確定した重大な誤り（B 2 ／ A 0）、
停止規則1〜3の「該当」が載っている。**これらは判定装置が安定しなかった状態での参考値であり、
効果がある根拠にも、無い根拠にも使わない。** 記録として、集計コードの出力のまま公開する。

そのほかの補足：

- `REPORT.md` §6 の「Claude（?）」は、判定結果のファイルにモデル名の欄が無いためである。
  起動記録では40件とも `claude-opus-5` だった。公開した `judgements.public.csv` でも、Claude 側の `judge_model` は空欄になっている
- 盲検が崩れうる2組は `REPORT.md` 本文に載っていない（集計コードに併記の処理が無かった）。値は §3 に書いた
- `DESIGN.md` §8 は「v2 を付録にする」としていたが、v2 の後付け判定を行っていないため付録は無い

## 6. 限界

- **測ったのは、同じモデル上での整形の効果だけである。**「モデル選び＋整形」をまとめた効果は測っていない。
  B を作ったときに which-model が出した通常推奨と、実験での割当は次のとおりだった
  （推奨は空のフォルダで出したもので、リポジトリの中身は見ていない）

  | タスク | 割当 | 通常推奨（1回目 ／ 2回目） |
  | --- | --- | --- |
  | t01 | Sonnet 5 / medium | Sonnet 5 / low ／ Sonnet 5 / low |
  | t02 | Sonnet 5 / medium | Sonnet 5 / medium ／ Sonnet 5 / medium |
  | t03 | Sonnet 5 / medium | **Opus 5 / high** ／ Sonnet 5 / low |
  | t04 | Opus 5 / high | **Sonnet 5 / medium** ／ **Sonnet 5 / medium** |
  | t05 | Opus 5 / high | **Sonnet 5 / medium** ／ **Sonnet 5 / medium** |
  | t06 | Opus 5 / high | **Fable 5.1 / high** ／ **Fable 5.1 / high** |
  | t07 | Fable 5.1 / high | **Sonnet 5 / low** ／ **Sonnet 5 / low** |
  | t08 | Fable 5.1 / high | **Sonnet 5 / low** ／ **Sonnet 5 / low** |
  | t09 | Fable 5.1 / high | **Sonnet 5 / low** ／ **Sonnet 5 / low** |
  | t10 | Sonnet 5 / medium | Sonnet 5 / medium ／ Sonnet 5 / medium |

  20本のうち、モデルが違ったのが13本（太字）、モデルは同じで effort が違ったのが3本、両方一致したのは4本（t02・t10）

- 判定者どうしの一致率を、本番の前に確かめていない（§3）
- 判定基準は「どう比べるか」の優先順位であり、タスクごとの正解（押さえるべき点）は定めていない
- 10タスク・読み取り専用・うち7件が同じリポジトリ。新しい依頼は集めていない
- 2つの判定者が同じ誤りをした場合は検出できない
- Codex の判定は `gpt-6-astra` の1版だけで行った
- モデル別の差は結論にしない（Fable 5.1 3件 ／ Opus 5 3件 ／ Sonnet 5 4件）

## 8. 公開物の作り方（`bin/publish.sh` からの変更）

`bin/publish.sh` は、`REPORT.md` が「状態：完了」でないと止まる。凍結対象なので書き換えず、
凍結対象外の `checks/publish_closing.sh` で公開物を作った。**公開する範囲（許可リスト）は `bin/publish.sh` と同じ**で、
変えたのは次の点である。

1. 完了状態の確認の代わりに、この文書があることを確認する。この文書も公開する
2. 公開前に、凍結87ファイルが `manifest.json` と一致することを確認する
3. `REPORT.md` の公開版の冒頭に、未完了の集計であることと、この文書への案内を追記する（本文は変えない）
4. **t06 の依頼文を載せない。** `DESIGN.md` §8 は t06 だけ全文を載せる設計だったが、
   「依頼文は出さない」という 2026-09-17 の作者の決定を優先した。`tasks.public.json` には文字数と SHA-256 だけを載せる
5. **公開コピーだけ、私有リポジトリ名とローカルのパスを伏せ字にする。** 元のファイルと `manifest.json` は変えていない

   | 置換前 | 置換後 |
   | --- | --- |
   | ローカルの絶対パス | `<local-path>` |
   | 7件を参照した私有リポジトリの名前 | `<private-repo-1>` |
   | 2件を参照した私有リポジトリの名前 | `<private-repo-2>` |
   | 私有リポジトリを置いていたフォルダ名（3種） | `<private-dir-1>`〜`<private-dir-3>` |

   伏せ字にした次の公開コピーは、`manifest.json` のハッシュと**一致しない**（元のファイルは一致する）：
   `DESIGN.md`・`STOP-RULES.md`・`harness/config.json`・`harness/bin/publish.sh`。
   `publish.sh` と `publish_closing.sh` の公開コピーでは、検査する語の一覧も伏せ字になっているため、
   そのままでは流出検査として機能しない

6. 公開物の作成に使った `checks/publish_closing.sh` も、同じ伏せ字をかけて `harness/checks/` に置く
7. 私有パス・プロジェクト名の検査は残した。伏せ字をかけた後の公開物全体に対して行い、1件でも見つかれば公開物を作らない

**公開していないもの**：依頼文、回答本文、B のプロンプト、判定理由、作業記録（盲検の記録・一時停止と再計画の記録など）。
いずれも私有リポジトリの内容や構造を含むためである。
