# 停止規則 v3（実行前に固定・結果を見て変更しない）

作成: 2026-09-09 ／ **この文書は本実行の前に凍結する**（`manifest.json` にハッシュを記録）。
凍結後にこの文書が変わっていると `bin/run.sh` 以降は実行を拒否する。

---

## 0. これが何か

軸2（プロンプト整形）の価値信号があるかを、**結果を見る前に決めた基準**で判定するための規則。
基準を後から動かせば、どんな結果でも「価値あり」に読める。それを封じるためにここへ固定する。

判定対象は次の一点だけ。

> **2026-09 時点の現行モデル（Fable 5.1 / Opus 5 / Sonnet 5）で、which-model が生成した
> プロンプト B は、素の依頼 A より利用者にとって有用か。**

利用者の仮説「モデルが賢くなり、曖昧な指示でも良い出力が出るようになった」は、この問いに対する
**最も強い反証仮説**として扱う。B が A に勝てなければ、軸2の主張は残らない。

**モデル固有ガイドの追加価値（B vs C）は今回測らない。** B が A を上回らなければ C を作り直す
意味がないため。**モデル選定（軸1）も測らない。** モデルと effort は各タスク内で A/B とも同一に固定する。

## 0-2. 完了ゲート（停止規則より先に効く）

**次がすべて揃うまで、停止規則を適用して結論を出さない。** 揃っていない場合の結論は
`INCOMPLETE / 判定保留` であって、「価値信号なし」ではない。

1. 予定された run（タスク × 2腕 × 反復）が**全件** `status=ok`
   - `is_error=true` の応答は**本文があっても `ok` にしない**
   - 与えたはずのツールが拒否された run も `ok` にしない
   - **指定した model_id と実測（`system/init` の `model`）が違う run も `ok` にしない**
     （`model_mismatch` / `actual_model_unknown`）
2. Claude judge（J1）の判定が**全件**取得済み
3. **Codex judge（J2）の判定が全件取得済み**
4. **J1 と J2 が割れた比較単位の人間確認が全件投入済み**

**理由：** 実行・判定スクリプトは失敗を WARN で記録して先へ進む（再開を容易にするため）。
このゲートが無いと、API 障害で run が欠けただけで「B勝ち3件未満 ＝ 価値信号なし」に落ちる。
**装置の失敗を製品の評価に化けさせない**ための規則である。

## 1. 用語と確定規則

- **比較単位** … `(タスク, 反復)` の対。反復数は `config.json` の `reps`（v3 は **2**）。
- **系統ごとの確定勝者** … その系統（J1 / J2）について、左右を入れ替えた2回の pairwise 判定を
  腕（A/B）へ写像し、**2回の勝者が一致したときだけ確定**する。一致しなければ `unresolved`。
- **比較単位の勝者** … 次の表で決める。

| 状況 | 確定 |
| --- | --- |
| **J1 = J2 ∈ {A, B, 引き分け}** | **自動確定**。final = J1 |
| J1 ≠ J2、またはどちらかが `unresolved` | **人間確認へ**（盲検 X/Y）。`human/<unit>.json` が final |

**判定の腕への写像**（J1 / J2 で同一のコードを使う）

| 提示順 | verdict | 腕の勝者 |
| --- | --- | --- |
| 左=A / 右=B | `left_better` | A |
| 左=A / 右=B | `right_better` | B |
| 左=B / 右=A | `left_better` | B |
| 左=B / 右=A | `right_better` | A |
| いずれ | `tie` | 引き分け |
| いずれ | `critical_error_<側>` | **相手側の勝ち**。加えてその側に critical error を1件記録 |

`critical_error` を相手の勝ちに写像するのは、判定の優先順位1が「技術的・事実的に正しい」であり、
重大な誤りがある側は他の項目で挽回しない、と事前に決めたためである。

**critical error は「両系統が同じ腕に報告したときだけ確定」とする。** 片方だけの報告は
「未確定」として件数を出すが、規則3の集計に入れない。**critical の食い違いだけでは人間確認へ
回さない**（勝者が一致しているなら final は確定する）。

**ツール未使用の判定は採用しない。** `context_required=true` の比較で judge がツールを1回も
使わなかった判定は、実装と照合していないので**判定失敗としてリトライする**（J1 / J2 で同基準。
片方の系統だけに課すと基準が非対称になり、系統間の一致率が比較にならない）。

### タスクの勝者（反復2）

| 2比較単位の内訳 | タスクの勝者 |
| --- | --- |
| B勝ち + B勝ち | **B** |
| B勝ち + 引き分け | **B** |
| A勝ち + A勝ち | **A** |
| A勝ち + 引き分け | **A** |
| 引き分け + 引き分け | 引き分け |
| B勝ち + A勝ち | **反転**（勝者なし） |
| 未確定を含む | **保留** |

**反転と保留は「B勝ちタスク」に数えない。**

### 人間確認も盲検で行う

確認者に見せるのは `review/<比較単位>/X.md` と `Y.md` だけで、**どちらが which-model 版かは
開示しない。** X/Y の割当は seed から決まり `plan.json` の `blind_map` に凍結されている
（pairwise の左右割当とは別の抽選なので、judge の提示順から腕を推測できない）。

確認者は `X` / `Y` / `tie` で答え、集計側が腕へ写像する。
**`A` / `B` で書かれた確認結果は盲検が破れている証拠としてエラーで弾く。**

## 2. 停止規則

集計は**人間確認を反映した後の確定値**で行う。

| # | 規則 | 該当したときの結論 |
| --- | --- | --- |
| 1 | **B勝ちタスク数が3件未満** | 価値信号なし |
| 2 | **B勝ちタスク数が A勝ちタスク数以下** | 価値信号なし |
| 3 | **確定した critical error が B ≥ 2 かつ B > A** | 価値信号なし |
| 4 | **judge 間の食い違い率が 1/3 を超える** — 両系統の判定が揃った比較単位のうち、J1 ≠ J2（`unresolved` を含む）の割合 | **判定不能** |

**規則1〜3のいずれかに該当したら「価値信号なし」と判定し、B/C 試験へ進まない。**
**規則4に該当したら結論は「判定不能」**であって、価値があるとも無いとも言わない。
判定装置が信頼できないことと、製品に価値が無いことは別だからである。この場合は判定装置の設計へ戻る。

**どれにも該当しない場合に限り**、軸2は「価値信号あり（弱い探索的信号）」とし、
B/C 試験（モデル固有ガイドの追加価値）の設計へ進んでよい。

### 規則4を人間校正から judge 間一致へ替えたことで失うもの（明示）

v2 の規則4は人間が judge を校正していた。v3 では人間は「割れたとき」しか見ないので、
**両 judge が同じ誤りをした場合は検出できない。** 得るものは、人手を不一致分に限れること。
この取引は 2026-09-09 の利用者の決定に基づく。**結論を読むときはこの穴を前提にすること。**

### 規則に含めないと決めたもの（明示）

- **コストは停止規則に入れない。** B の総コスト増減は記録・報告するが、それ単独では進退を決めない。
  「B が勝ったが著しく高い」場合の扱いは、信号が出てから別途決める。
- **統計的検定（Wilcoxon・bootstrap CI・相関係数）を主結論に使わない。** 標本が少なすぎる。
  タスク単位の勝敗の数え上げだけを見る。

## 3. 結論の書き方の制約

- 「差がなかった」ではなく「**この規模では差を検出できなかった**」と書く。
- 勝敗数は率（%）で書かず、`B 4 / A 1 / 引き分け 3 / 反転 1` の形で書く。
- タスクが8件に満たないまま実行した場合、その旨と件数を結論に併記する。
- **同一タスクの反復を独立タスクとして数えない。**
- **モデル別の差を結論にしない**（構成は Fable 5.1 3件 / Opus 5 3件 / Sonnet 5 4件）。
- **読み取り専用タスクの範囲でしか言えない。**
- **Fable 腕が Fable 5 に落ちた場合は、skill の筆頭推奨（5.1）を測っていない**と明記する。
- 否定的な結果でも公開する（DESIGN.md §8）。
