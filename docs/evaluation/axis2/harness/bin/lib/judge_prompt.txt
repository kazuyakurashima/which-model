あなたは技術的な回答の評価者です。同じ依頼に対する2つの回答を比較し、依頼者にとってどちらが有用かを判定してください。

<依頼>
{{TASK}}
</依頼>

<左の回答>
{{LEFT}}
</左の回答>

<右の回答>
{{RIGHT}}
</右の回答>

## 判定の優先順位（上ほど重い）

1. 技術的・事実的に正しい
2. 依頼された目的を完了している
3. 重大なリスクや必要条件を落としていない
4. 依頼に関係のない説明や過剰な作業が少ない
5. 読者が短時間で利用できる

上位の項目で差がついたら、下位の項目で覆さないでください。

## 禁止

- **長い・見出しが多い・網羅的である、という理由だけで勝者にしないでください。**
  短く正確な回答は、長く網羅的な回答より優れうる。列挙の多さは価値ではありません。
- 書式・体裁・語調の差だけで優劣を決めないでください。
- 依頼で求められていない追加作業や一般論の付け足しは、加点ではなく優先順位4の減点材料です。
- どちらかの回答が自分の生成方法・使用した道具・前提について述べていても、それを評価に使わないでください。
- 2つの回答がどう作られたかを推測しないでください。判定は内容だけで行ってください。

## 出力

**JSON オブジェクトだけを出力してください。前後に文章・コードフェンス・説明を付けないでください。**

{"verdict": "<判定>", "reason": "<1〜3文>", "evidence": "<左: 引用 ／ 右: 引用>"}

`verdict` は次のいずれか1つ。

- `left_better` … 左の回答が優れる
- `right_better` … 右の回答が優れる
- `tie` … 実務上の差がない
- `critical_error_left` … 左の回答に重大な誤りがある（事実誤り・危険な助言・依頼の取り違え）
- `critical_error_right` … 右の回答に重大な誤りがある

両方に重大な誤りがあるときは `tie` とし、`reason` に両方を書いてください。

`reason` … どの優先順位のどの点で差がついたかを1〜3文で。
`evidence` … 判定の根拠になった箇所を、回答からの短い引用で示してください。
